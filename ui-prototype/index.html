          На кадре выделите мышью область, которую надо закрыть. Это локальная проверка макета: загруженная картинка не доказывает, что показана игра, числа условные.

          PNG макета создаётся локально только по кнопке. Прототип не захватывает игру и не создаёт .yawa; никаких данных не отправляет.

          Как считаем

          оба источника показаны отдельно: живые замеры точнее любого справочника

          Во время игры берём загрузку процессора (с учётом самого занятого ядра) и видеокарты: узкое место — тот узел, что ближе к 100 %, а процент показывает, насколько простаивает второй. Если игры нет, считаем прогноз по индексам производительности и разрешения экрана: потолок CPU от пикселей почти не зависит, потолок GPU падает при росте разрешения. Прогноз — оценка ±15 % и живые замеры он не заменяет.

              Видеокарты

              DXGI и реестр класса Display

                Память

                SMBIOS Type 17: раскладка по слотам, частоты и напряжение модулей

                —

                    Действующие тайминги: недоступны в демо. В приложении они читаются из контроллера UMC только на подтверждённом AMD DDR4; SPD хранит паспортные профили, а не текущие значения.

                    Мониторы

                    EnumDisplaySettings и EDID-имя драйвера монитора

                      Диски

                      Модель из Windows · SMART только при точном совпадении номера диска

                        Откуда эти числа

                        реестр, CPUID, SMBIOS, DXGI и EnumDisplaySettings — без драйверов и без сети

                        Версию Windows берём из CurrentVersion — оттуда же её берёт winver, поэтому карточка и окно «О системе» совпадают. Модель процессора читается прямо из CPUID, ядра и кэш — из GetLogicalProcessorInformationEx. Видеокарты перечисляет DXGI, а версию драйвера добавляет реестр класса Display. Модули памяти и их частоты приложение берёт из таблиц SMBIOS, которые BIOS собирает из SPD: именно так видно «2×16 ГБ», а не только «32 ГБ» суммарно.
