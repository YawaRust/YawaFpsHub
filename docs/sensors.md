# Источники показателей

Разведка перед реализацией: что уже есть открытого, под какой лицензией и что из этого
можно взять, оставшись портативным приложением без сторонних зависимостей и драйверов.

## Кадры: ETW вместо инъекций

| Проект | Лицензия | Как получает кадры | Почему не берём целиком |
|---|---|---|---|
| [GameTechDev/PresentMon](https://github.com/GameTechDev/PresentMon) | MIT | ETW-сессия реального времени, провайдеры DXGI, D3D9, DxgKrnl, DWM | Зависимость на 100k строк, служба и собственная модель данных; нам нужен только потребитель Present-событий |
| RTSS / MSI Afterburner | закрытый код | хуки в `Present` внутри процесса игры | Требует инъекции DLL: античиты и антивирусы реагируют, для портативного монитора это неприемлемый риск |
| fps_inspector_sdk | без явной лицензии | ETW | Лицензия не позволяет встраивание |

Взято из PresentMon: GUID и идентификаторы событий (сверены с `PresentData/ETW/*.h`),
настройки сессии (буфер 64 КБ, 256…1024 буфера, `EVENT_TRACE_REAL_TIME_MODE`, метка времени
QPC). Код потребителя написан свой, без зависимости.

Используемые провайдеры:

| Провайдер | GUID | Событие | ID |
|---|---|---|---|
| Microsoft-Windows-DXGI | `CA11C036-0102-4A2D-A6AD-F03CFED5D3C9` | `Present_Start` | 0x2A |
| Microsoft-Windows-D3D9 | `783ACA0A-790E-4D7F-8451-AA850511C6B9` | `Present_Start` | 0x0001 |

Кадром считается `Present_Start`: `Present_Stop` закрывает тот же кадр, и учёт обоих
событий удваивал бы FPS. Ключ провайдеров — `0x8000000000000002` (Analytic + Events).
Вызовы с флагом `DXGI_PRESENT_TEST` (проверка окна без кадра) отбрасываются.

### Чей FPS показывать: как в RTSS

Кадры в сессию приходят от всех процессов сразу. Раньше «игрой» считался самый быстрый
поток, и на мониторе 144 Гц композитор рабочего стола (`dwm.exe`) обгонял игру со 120
кадрами — программа показывала 144. Теперь порядок такой:

1. процесса активного окна (`GetForegroundWindow` → pid), если он не служебный;
2. иначе самый быстрый поток, но служебные процессы (`dwm.exe`, `explorer.exe`, хосты
   оболочки, `csrss.exe` и т.п.) вперёд не выдвигаются никогда.

Цифра FPS считается по последней секунде (сумма интервалов кадров за окно 1000 мс), как в
RTSS, а не по одному последнему кадру: иначе значение дрожит и расходится с тем, что видит
игрок.

Ограничение: Vulkan- и OpenGL-игры презентуют через DWM, их кадры в этих событиях не видны —
для них остаётся оценка по композитору (этап 5).

## Загрузка и память GPU

- **DXGI** (`IDXGIFactory1`, `IDXGIAdapter1::GetDesc1`, `IDXGIAdapter3::QueryVideoMemoryInfo`) —
  имена, LUID, объём, бюджет и занятость видеопамяти. Без прав администратора, без драйверов.
- **PDH** `\GPU Engine(*)\Utilization Percentage` — тот же источник, что у диспетчера задач;
  инстансы содержат LUID адаптера, поэтому два GPU не смешиваются.

## Медиа-движки, PCI-e и файл подкачки

| Датчик | Источник | На чём работает |
|---|---|---|
| Кодирование видео | PDH `\GPU Engine(*)\Utilization Percentage`, инстанс `engtype_VideoEncode` по LUID | NVIDIA, AMD, Intel — движок общий для всех трёх |
| Декодирование видео | тот же счётчик, `engtype_VideoDecode` | NVIDIA, AMD, Intel |
| Кодирование/декодирование (уточнение) | NVML `nvmlDeviceGetEncoderUtilization` / `GetDecoderUtilization` | только NVIDIA; берётся максимум с PDH-значением |
| Нагрузка PCI-e | NVML `nvmlDeviceGetPcieThroughput` (TX+RX) к теоретической пропускной способности линии (`GetCurrPcieLinkWidth` × `GetCurrPcieLinkGeneration`) | только NVIDIA; на AMD и Intel честно «нет данных» |
| Загрузка ОЗУ | `GlobalMemoryStatusEx`: занято / всего, % | везде |
| Загрузка файла подкачки | занято / (commit limit − физическая память), % | везде |
| Объём файла подкачки | `GetPerformanceInfo`: commit limit − физическая память, всего и занято | везде |
| Объём файла подкачки (всего) | `GetPerformanceInfo`: commit limit − физическая память | везде |

Медиа-счётчики `engtype_VideoEncode`/`engtype_VideoDecode` появляются только когда игра или
браузер реально нагружает движок, поэтому нулевые значения — это нормальный ответ, а не
отсутствие драйвера. Если для выбранного LUID ни одного инстанса нет, датчик пишет «нет данных».

`yawa-probe` печатает строку «Медиа-движки да/нет, PCI-e да/нет, файл подкачки да/нет»:
по ней видно, что поднялось на конкретной машине.

## Проверка на разном железе

Что проверяется и чем, без установки драйверов и SDK:

| Железо | Загрузка GPU | Медиа-движки | PCI-e | Температура GPU |
|---|---|---|---|---|
| NVIDIA (GeForce/RTX) | PDH GPU Engine | PDH + NVML | NVML | NVML |
| AMD (Radeon, iGPU 780M) | PDH GPU Engine | PDH GPU Engine | нет данных | нет данных (ADLX — этап 5) |
| Intel (Arc, Iris Xe) | PDH GPU Engine | PDH GPU Engine | нет данных | нет данных (IGCL — этап 5) |
| Любой x86/x64 CPU | `NtQuerySystemInformation` | — | — | ACPI-термозона |

Общее для всех — загрузка GPU, видеопамять (DXGI), память, диск, сеть, кадры и файл подкачки:
эти источники встроены в Windows и не зависят от производителя. Приватные API (NVML, ADLX,
IGCL) подключаются динамически и только для дополнительных показателей; их отсутствие не
ломает остальные датчики, а даёт «нет данных».

Проверка на конкретной машине: запустить `yawa-probe.exe` рядом с `YawaFpsHub.exe` и
посмотреть строки `GPU:`, `Медиа-движки`, `PCI-e`, `файл подкачки` и список адаптеров.

## Температуры, частоты, питание

| Источник | Что даёт | Лицензия / установка | Решение |
|---|---|---|---|
| NVML (`nvml.dll`) | температура, частоты, питание, вентилятор NVIDIA | ставится с драйвером, проприетарная, но бесплатная | берём, грузим динамически |
| ADLX / ADL (`atiadlxx.dll`) | то же для AMD | SDK AMD, библиотека в драйвере | этап 5 |
| IGCL | то же для Intel | SDK Intel | этап 5 |
| [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) | MSR и SMBus: температуры CPU, чипсета, NVMe | MPL-2.0, **требует kernel-драйвер** | не берём: драйвер ломает портативность и требует подписи |
| PDH `\Thermal Zone Information(*)\Temperature` | температура ACPI-термозоны | встроено | первый источник: читается раз в опрос, без COM |
| WMI `MSAcpi_ThermalZoneTemperature` | та же термозона через WMI | встроено | второй источник: включается, когда PDH молчит; запрос не чаще раза в 15 с |
| WMI `Win32_PerfFormattedData_Counters_ThermalZoneInformation` | та же термозона, другой класс | встроено | третий источник: `HighPrecisionTemperature` (десятые Кельвина) и `Temperature` (Кельвины) |

Порядок такой: PDH-счётчик термозоны → WMI `root\WMI` → «нет данных». Первый источник
почти ничего не стоит, второй дороже, поэтому вызывается только при отсутствии значения и
не чаще раза в 15 секунд; при провале WMI больше не дёргается до перезапуска. На части плат
(особенно виртуальные машины и desktop-платы без ACPI-термозоны) оба источника честно
отсутствуют — тогда в интерфейсе «нет данных», а не ноль.

### Драйверов нет вообще

Приложение не устанавливает и не загружает ни одного драйвера: ни kernel-драйвера для MSR,
ни SMBus, ни собственной службы. Температура CPU — это ACPI-термозона, которую прошивка
отдаёт либо счётчиком PDH, либо классом WMI; всё это части Windows. Поэтому exe остаётся
одним файлом: он не просит права администратора, не ставит службу и не оставляет следов
в системе. Плата за это — на части материнских плат и в виртуальных машинах прошивка
термозону не публикует, и тогда честно пишется «нет данных», а не выдуманное число.

Питание CPU без драйвера уровня ядра прочитать нельзя: RAPL/MSR требуют kernel-драйвера,
поэтому «Питание» показывает значение только там, где его отдаёт встроенный источник, и
иначе пишет «нет данных». `yawa-probe` печатает список того, что реально поднялось на
конкретной машине.

Имя процессора для карточки «Процессор» берётся из
`HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0\ProcessorNameString`, чистится от
`(R)`, `(TM)`, «CPU», «N-Core Processor» и «@ x.xxGHz» — остаётся «Ryzen 7 7800X3D».

## Монитор

Разрешение и герцовка основного экрана читаются через `EnumDisplaySettingsW(ENUM_CURRENT_SETTINGS)`,
имя — через `EnumDisplayDevicesW`. Они показываются в подзаголовке карточки «Кадры в секунду»,
на экране «Настройки» и служат целью кадра по умолчанию (`target_auto = 1`), чтобы бюджет кадра
считался от реальной герцовки, а не от константы 60 Гц.

## Паспорт машины и узкое место

Экраны «Сведения о системе» и «Баланс системы» не спрашивают ничего у производителя железа:
всё берётся из встроенных источников Windows,те же используются один раз при запуске.

| Данные | Источник | Если источник молчит |
|---|---|---|
| Модель и вендор CPU | `__cpuid` (листы 0x80000002…0x80000004), резерв — `ProcessorNameString` из реестра | имя остаётся пустым, индекс не выдумывается |
| Ядра, потоки, кэш L3, SMT | `GetLogicalProcessorInformationEx(RelationAll)` | число потоков из `GetActiveProcessorCount`, ядра не указываются |
| Базовая частота | `HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0\~MHz` | «нет данных» |
| Модель Windows, версия функционала, сборка | `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` — то же, что читает `winver` (`ProductName`, `DisplayVersion`, `CurrentBuildNumber`, `UBR`, `EditionID`); сборка ≥ 22000 отображается как Windows 11, потому что реестр по-прежнему пишет «Windows 10» | пустые строки |
| Список видеокарт, вендор, объём памяти | DXGI (`EnumAdapters1`), общий реестр `GpuRegistry` | список пуст |
| Версия драйвера видеокарты | `MatchingDeviceId` + `DriverVersion` из `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-…}` по PCI-идентичности адаптера | строка «нет данных» |
| Модули памяти: слот, объём, тип, частота SPD, рабочая частота, вендор, партномер, напряжение | `GetSystemFirmwareTable('RSMB')` — SMBIOS Type 16 (число слотов) и Type 17 (планки) | показывается только полный объём из `GlobalMemoryStatusEx` |
| Мониторы: имя, разрешение, герцовка, масштаб | `EnumDisplayDevicesW` + `EnumDisplaySettingsExW(ENUM_CURRENT_SETTINGS)`, `GetDpiForSystem` | пустой список |

**Тайминги ОЗУ.** `tCL-tRCD-tRP-tRAS` живут в SPD на шине SMBus. Читать их можно только через
драйвер уровня ядра, а загрузка драйверов запрещена правилами проекта и убивает смысл
портативного exe. Поэтому в карточке памяти показывается то, что BIOS отдаёт честно: тип,
паспортная и рабочая частоты, отсюда — такт `tCK = 2000 / MT/с` в наносекундах, напряжение и
признак невыключенного XMP/EXPO (рабочая частота ниже паспортной). Выдуманные «16-18-18-38»
в интерфейсе не появятся.

### Как считается узкое место

Два источника, и оба показаны на экране отдельно.

1. **Живые замеры** (игра запущена, датчики отдают данные). Давление процессора —
   `max(общая загрузка, 0,9 × самое занятое ядро)`: однопоточный упор по сумме процентов
   ядер не виден. Давление видеокарты — `gpu_load`. Узкое место — тот узел, что ближе к
   100 %, а процент показывает, насколько простаивает второй: `100 × (1 − меньше / больше)`.
   Разница меньше 12 % — «связка работает ровно». Отдельно перехватываются три случая,
   где загрузка вводит в заблуждение: заполненная видеопамять, кадр на уровне цели
   (`fps ≥ 0,96 × target`) и отсутствие нагрузки вообще.
2. **Прогноз по индексу** (игры нет). Индексы CPU и GPU пересчитываются в потолок кадров:
   `потолок CPU = индекс × 3,2` от разрешения почти не зависит, `потолок GPU = индекс × 2,6 ×
   (1080p / пикселей)^0,85` — степенной показатель, потому что часть работы (подача кадров,
   постобработка) от числа пикселей не растёт. Ниже 12 % расхождения — «сбалансировано».
   Это оценка ±15 %, и в интерфейсе она помечена словом «оценка».

Рекомендации генерируются от вывода, а не печатаются списком подряд: при упоре в процессор
это перенос нагрузки на GPU (повысить разрешение или DSR/VSR), настройки, снижающие нагрузку на CPU,
лимит кадра и проверка однопоточности; при упоре в видеокарту — апскейлер, тяжёлые для GPU
эффекты, нехватка видеопамяти и лимит питания. Отдельные пункты включаются только если
условие видно по данным: XMP/EXPO выключен, память в один канал, ОЗУ занято больше 90 %.

### Что видно на разном железе

| Платформа | Паспорт и индекс | Живое узкое место |
|---|---|---|
| NVIDIA (GeForce) | имя из DXGI, драйвер из реестра, температуры/питание из NVML | загрузка CPU и GPU есть → расчёт по замерам |
| AMD (Radeon) | имя и объём из DXGI, версия драйвера из реестра; NVML нет | загрузка GPU из PDH-движков есть → расчёт по замерам; питание и температуры — «нет данных» |
| Intel (Arc, Iris, UHD) | имя и объём из DXGI, драйвер из реестра | то же; для iGPU индекс получается низким, поэтому прогноз честно говорит об упоре в GPU |
| Без дискретной карты | встроенный адаптер становится «основным» | прогноз по индексу, рекомендации по разрешению не показываются |
| Виртуалка / Basic Render Driver | CPU и память определяются, GPU — «нет данных» | экран «Баланс» показывает «Недостаточно данных» |

## Остальное

- **PDH** `\Processor Information(_Total)\% Processor Performance` × номинальная частота из
  `HKLM\HARDWARE\...\~MHz` — текущая частота CPU.
- **`CallNtPowerInformation(ProcessorInformation)`** из `powrprof.dll` — резервный источник
  частоты: работает без счётчиков PDH и без драйверов. Если молчит и он, показывается
  номинал из реестра, чтобы строка не оставалась пустой.
- **PDH** `\PhysicalDisk(_Total)\Disk Read Bytes/sec` и `\Network Interface(*)\Bytes Received/sec` —
  уже готовые скорости; повторно брать дельту нельзя, иначе значения уезжают в миллиарды
  (эта ошибка была поймана прогоном `yawa-probe` в CI).
- **`GetSystemTimes`**, `GlobalMemoryStatusEx`, `GetPerformanceInfo` — загрузка CPU, память, кэш, своп.
- **`NtQuerySystemInformation(SystemProcessorPerformanceInformation)`** — загрузка по ядрам:
  время простоя и полное время каждого логического процессора, проценты считаются по дельте
  между опросами, как в диспетчере задач. PDH-счётчики `\Processor Information(0,N)\...` здесь
  не используются: на части машин экземпляры не открываются, и датчики оставались пустыми.
- **`GetForegroundWindow`**, `GetWindowThreadProcessId`, `OpenThread`, `GetThreadTimes` + QPC —
  «Поток игры»: загрузка главного потока активной игры. Без запущенной игры датчик честно
  показывает «нет данных», а не ноль.
- **`GetProcessTimes`**, `GetProcessMemoryInfo` — собственное потребление приложения.

Имена счётчиков запрашиваются через `PdhAddEnglishCounterW`: на русской Windows локализованные
имена обычный `PdhAddCounter` не находит.
