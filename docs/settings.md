# Формат YawaFpsHub.ini

Файл лежит в `%LOCALAPPDATA%\YawaFpsHub\YawaFpsHub.ini`. Реестр не используется:
приложению нужен только сам `YawaFpsHub.exe`, а состояние — этот файл и папка `sessions/`
рядом с ним. Если рядом с exe остался `YawaFpsHub.ini` от версии 0.x, он переносится в
каталог данных один раз при первом запуске.

Формат — обычный INI в UTF-8 без BOM. Неизвестные ключи игнорируются, отсутствующие берут
значения по умолчанию.

## [capture]

| Ключ | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `interval_ms` | 500, 1000, 2000 | `1000` | Период опроса, как в диспетчере задач |
| `smoothing` | 0–90 | `40` | Сглаживание графиков, проценты |
| `etw_enabled` | `0`/`1` | `1` | Сбор кадров через ETW |
| `pause_when_idle` | `0`/`1` | `1` | В простое без кадров опрос замедляется до 2 с |
| `target_hz` | 30–480 | `60` | Целевая частота кадров для бюджета и пропусков |
| `target_auto` | `0`/`1` | `1` | При запуске брать цель кадра из герцовки монитора |
| `include_disk_net` | `0`/`1` | `1` | Показывать диски и сеть на обзоре и в датчиках |

## [gpu]

| Ключ | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `luid_low` | целое | `0` | Младшая часть LUID выбранного адаптера |
| `luid_high` | целое | `0` | Старшая часть LUID выбранного адаптера |

Если указанный LUID не найден (сменилась карта, другой компьютер), приложение выбирает
адаптер по умолчанию: дискретный с наибольшим объёмом видеопамяти. LUID, а не индекс,
используется специально: порядок адаптеров в DXGI меняется при смене набора мониторов.

## [overlay]

| Ключ | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `position` | `tl`, `tr`, `bl`, `br` | `tl` | Угол экрана при `anchor_mode = corner` |
| `anchor_mode` | `corner`, `free` | `corner` | Привязка к углу или свободное положение; прежние INI остаются угловыми |
| `origin_x`, `origin_y` | 0–32768 | `0` | Резервная позиция в виртуальном экране при `free` (прежний формат INI) |
| `saved_monitor_id` | путь интерфейса дисплея или `display:` + имя | не задан | Автоматически запоминается при новом перемещении свободной плашки; старый INI без ключа не мигрирует сам |
| `monitor_origin_x`, `monitor_origin_y` | 0–32768 | `0` | Пиксели от края сохранённого монитора; используются только вместе с `saved_monitor_id` |

| `recipe` | 16 ключей ниже | `frosted` | Рецепт формы, поверхности, шрифта и палитры; старый INI без ключа мигрирует по `style` без изменения оформления |
| `layout` | `plates`, `line`, `gauge` | `plates` | Форма: плитка, строка или шкала |
| `style` | `neon`, `rtss`, `frosted`, `terminal`, `cyber`, `mono`, `esport`, `retro` | `frosted` | Базовая палитра; оставлена для совместимости |
| `surface` | `glass`, `plate`, `outline`, `none`, `custom` | не задан | Ось поверхности; `custom` сохраняет ручные фон/рамку/тень нового рецепта, отсутствие ключа — старый вид |
| `scale` | 70–160 | `100` | Масштаб, проценты |
| `opacity` | 0–100 | `72` | Прозрачность фона, проценты |
| `offset_x` | -2000…2000 | `0` | Ручной сдвиг по горизонтали от выбранного угла, px |
| `offset_y` | -2000…2000 | `0` | Ручной сдвиг по вертикали от выбранного угла, px |
| `pixel_layout` | `0`/`1` | `0` | Независимые позиции подписей и значений в отдельном редакторе |
| `show_fps` | `0`/`1` | `1` | Строка FPS в оверлее |
| `show_cpu` | `0`/`1` | `1` | Строка загрузки процессора |
| `show_gpu` | `0`/`1` | `1` | Строка загрузки видеокарты |
| `show_ram` | `0`/`1` | `1` | Строка занятой памяти |
| `show_vram` | `0`/`1` | `1` | Строка видеопамяти |
| `background` | `0`/`1` | `1` | Подложка оверлея |
| `border` | `0`/`1` | `1` | Рамка вокруг оверлея |
| `shadow` | `0`/`1` | `1` | Мягкая тень под оверлеем |
| `corner` | -1…24 | `-1` | Радиус углов, px; `-1` — радиус из пресета |
| `font` | 0…3 | `0` | Шрифт: 0 — пресета, 1 — моноширинный, 2 — узкий, 3 — плотный |
| `bold` | `0`/`1` | `0` | Полужирное начертание |
| `italic` | `0`/`1` | `0` | Курсив |
| `text_outline` | 0…3 | `0` | Обводка текста, px (контрастная подложке) |
| `text_scale` | 85…130 | `100` | Размер шрифта, % (независимо от масштаба плашки) |
| `bg_opacity` | -1…100 | `-1` | Прозрачность подложки, %; `-1` — из пресета |
| `padding` | -1…28 | `-1` | Внутренние отступы, px; `-1` — из пресета |
| `row_gap` | -1…14 | `-1` | Межстрочный интервал, px; `-1` — из пресета |
| `value_color` | -1…5 | `-1` | Цвет значений; `-1` — из пресета, 0…5 — палитра |
| `label_color` | -1…5 | `-1` | Цвет подписей; `-1` — из пресета, 0…5 — палитра |
| `accent_color` | -1…5 | `-1` | Цвет акцента (линии, рамка, заголовки); `-1` — из пресета |
| `row_color_fps`, `row_color_cpu`, `row_color_gpu`, `row_color_ram`, `row_color_vram` | -1…5 | `-1` | Цвет значений отдельной строки |
| `border_width` | -1…3 | `-1` | Толщина рамки, px; `-1` — из пресета |
| `shadow_strength` | 0…100 | `100` | Сила тени, % от пресета |
| `letter_spacing` | 0…200 | `100` | Межбуквенный интервал, % от пресета |
| `uppercase` | -1…1 | `-1` | Подписи заглавными: `-1` — как в стиле, `1` — включить, `0` — выключить |
| `separators` | -1…1 | `-1` | Разделители строк: `-1` — как в стиле, `1` — включить, `0` — выключить |
| `fps_decimals` | -1…2 | `-1` | Знаки после точки у FPS в оверлее: `-1` — как в стиле |
| `click_through` | `0`/`1` | `0` | Сквозной клик: окно оверлея не перехватывает мышь (переключается хоткеем) |

Числовые значения в оверлее и его предпросмотре используют точку: `12.5 мс`,
`4.5 / 5.7 ГБ`. Подписи, текст «нет данных», формат остальных экранов и сохранённый
INI не меняются.

Масштаб увеличивает и текст, и плитки: кегли шрифтов пересчитываются вместе с геометрией,
поэтому оверлей растёт целиком, а не разъезжается. В режиме `corner` смещение прибавляется
к выбранному углу. В режиме `free` координаты `origin_x/y` отсчитываются от левого верхнего
угла **всего виртуального экрана** (включая мониторы слева и выше основного); при изменении
размеров экрана плашка ограничивается его границами. Редактор переводит плитки в режим
`free` при перетаскивании фона холста или Alt + перетаскивании строки; старый INI без ключа
`anchor_mode` продолжает работать в режиме `corner` с прежними смещениями.
`follow_game_monitor = 1` привязывает только **текущее отображение** к монитору
активной игры с кадрами; при потере игры приложение возвращается к сохранённым
координатам. Старый INI без флага сохраняет прежнее поведение. При новом
перетаскивании свободной плашки сохраняются идентификатор дисплея и локальные
координаты; старое положение в виртуальном экране остаётся резервным. При
перестановке экранов локальное положение восстанавливается, если дисплей найден;
при отключении идентификатор не заменяется соседним, плашка ограничивается
доступным экраном. Для некоторых виртуальных дисплеев доступно лишь имя
`\\.\DISPLAYn`, которое может смениться при перестановке. Эти сценарии и
поведение редактора после переподключения требуют проверки на Win32.

Рецепты `neon`, `rtss`, `frosted`, `terminal`, `cyber`, `mono`, `esport`, `retro`
соответствуют прежним восьми стилям. Новые: `fps_large` («Только FPS»), `stream`,
`laptop`, `hdr`, `recording`, `quiet`, `focus`, `clean`. Выбор рецепта сбрасывает
состав показателей на стандартный (у `fps_large` — только FPS), масштаб, форму,
типографику и ручные цвета/отступы; позиции, хоткеи и настройки датчиков не
трогает. Ручное переключение фона/рамки/тени выводит поверхность из выбранной
оси (`surface = custom` для новых рецептов), остальные оси остаются независимыми.

При чтении старого INI без `recipe` одноимённый рецепт определяется по `style`,
включая старые алиасы `glass`, `minimal`, `capsule`. Его значения не навязываются
старому файлу: явные `layout`, `font`, `background`, `border`, `shadow`, цвета и глазики
сохраняются. При следующем сохранении записывается `recipe`; отсутствие `surface`
по-прежнему означает прежнюю отрисовку. Новый рецепт применяется до остальных
ключей независимо от порядка строк, затем явные настройки имеют приоритет.

Кнопка «Экспорт JSON» в редакторе создаёт локальный файл со схемой `schema: 1`:
`recipe`, `palette`, `shape`, `surface` (или `null` у старого оформления),
`typeface`, `scale`. Необязательный объект `colors` содержит только заданные вручную
`value`, `label`, `accent`, `fps`, `cpu`, `gpu`, `ram`, `vram` в формате `#RRGGBBAA`.
Это **только описание оформления**, без индивидуальных цветов по ID показателей,
глазиков, имён игр, идентификатора дисплея и пользовательских подписей.
В браузерном прототипе импорт `schema: 1` принимает только эти поля и только файл
до 16 КБ. Неверный рецепт, поле или RGBA отклоняет целиком, без частичного применения.
Импорт изменяет оси оформления и общие цвета, но сохраняет состав показателей,
индивидуальные цвета, подписи, позицию и хоткеи. При `surface: "custom"` ручные
фон/рамка/тень остаются прежними — этих параметров в JSON нет. Win32-редактор
использует системный диалог выбора файла и такой же ограниченный импорт с проверкой
до применения; взаимодействие с диалогом и отрисовка ещё не проверены на Windows.
У шкалы заполняются лишь полосы достоверной загрузки CPU/GPU (0–100 %); остальные
строки имеют нейтральную дорожку, без придуманного процента.
Win32-отрисовка и экспорт через диалог сохранения пока не проверены на Windows.

`background`, `border`, `shadow` и `corner` — тонкая настройка поверх пресета: любой стиль можно
сделать совсем без подложки, без рамки или без тени, а скругление задать числом. Все
настройки доступны в отдельном редакторе; на экране «Оверлей» остался краткий предпросмотр.

`font`, `bold`, `italic` и `text_outline` — редактор текста: семейство, начертание и обводка
применяются ко всем подписям и числам оверлея, не меняя геометрию пресета.

`text_scale`, `bg_opacity`, `padding`, `row_gap`, цвета (`value_color`, `label_color`,
`accent_color`, `row_color_*`), `border_width`, `shadow_strength`, `letter_spacing`, `uppercase`,
`separators` и `fps_decimals` — ручная подстройка поверх пресета: размер шрифта отдельно от
масштаба плашки, своя прозрачность подложки, отступы и интервал строк, цвет каждой строки,
толщина рамки, сила тени, разрядка букв, регистр подписей, разделители строк и число знаков
после точки у FPS в оверлее. Значение `-1` (в интерфейсе
«из стиля») означает «как в пресете»; при смене стиля все ручные значения сбрасываются,
чтобы цвета одного пресета не переносились в другой.

Позицию можно менять и мышью: зажмите **Ctrl** и потяните оверлей. Пока Ctrl не нажат, окно
оверлея прозрачно для кликов и не мешает играть. Перетаскивание пишет `offset_x`/`offset_y`
(диапазон -2000…2000) и сохраняет их в ini по отпускании кнопки.

Стили оверлея — восемь пресетов из Fpsmon2.0. Стиль меняет палитру, типографику, форму
и компоновку, а не только подложку:

- `neon` — тёмный фон с неоново-зелёным акцентом и сеткой показателей;
- `rtss` — как RivaTuner: без подложки и рамки, крупный моноширинный;
- `frosted` — светлое матовое стекло с мягкой тенью;
- `terminal` — чёрный бокс, янтарная рамка, широкий трекинг;
- `cyber` — пурпур, угловые скобки и цветные значения по устройствам;
- `mono` — только текст на полупрозрачной плашке, без рамки;
- `esport` — плотная горизонтальная полоса для турниров;
- `retro` — фосфорный зелёный с развёрткой ЭЛТ.

Ключи прошлых версий (`glass`, `minimal`, `capsule`) читаются и переводятся в `frosted`,
`mono` и `esport` соответственно.

## [overlay_metrics]

Состав оверлея меняется через «+ Датчик» и поиск непосредственно в редакторе.
Каждый ключ таблицы датчиков (`fps`, `cpu_load`, `cpu_temp`, `gpu_clock`,
`ram_load`, `page_file_load`, `disk_read`, `net_down`, `core0_load` и остальные)
хранит независимое значение `0`/`1`. Глазик меняет только соответствующий ключ.
Все выбранные датчики передаются в оверлей и предпросмотр. Парные измерения
(`vram_used`/`vram_total`, `ram_used`/`ram_free`, `page_file`/`page_file_total`)
занимают одну строку, но исходные выборы сохраняются. Старый ключ `cpu_peak`
сохраняется при чтении настроек для совместимости, но не выводится: загрузка CPU
показывается отдельно, без «пика». Недоступное значение отображается как
«нет данных», а не исчезает.

Если секции нет, выбор переносится из старых `show_fps`, `show_cpu`, `show_gpu`,
`show_ram`, `show_vram`. Новая секция имеет приоритет над этими ключами.
Пустая подпись скрывает только название, но не выбранный показатель.

## [overlay_labels] и [overlay_metric_colors]

Ключи — имена датчиков из `[overlay_metrics]`. `[overlay_labels]` хранит индивидуальную
подпись до 64 символов UTF-8, включая кириллицу. Присутствующий ключ с пустым значением
скрывает подпись, не удаляя показатель; отсутствие ключа возвращает исходную подпись.
`[overlay_metric_colors]` хранит цвет значения: `-1` — от стиля или общих настроек,
`0`…`5` — выбранный цвет палитры. Эти поля настраиваются в инспекторе строки редактора:
поле RGBA принимает `#RRGGBBAA` при потере фокуса, пустое поле удаляет личный цвет.
В отличие от общих `row_color_*` они работают для каждого поддерживаемого датчика.
Дополнительные `value_rgba`, `label_rgba`, `accent_rgba`, `row_rgba_fps`…`row_rgba_vram`
и секция `[overlay_metric_rgba]` принимают строго `#RRGGBBAA` (включая альфу).
Пять `row_rgba_*` соответствуют типу показателя, а не его номеру в списке: смена
порядка строк не меняет группу цвета. В Win32-мастерской для групп FPS, CPU, GPU,
RAM, VRAM предусмотрены отдельные строки палитры и выбор произвольного RGB (альфа
уже заданного RGBA сохраняется при выборе RGB). Они имеют приоритет над индексами
старой палитры; отсутствие ключа сохраняет прежний вид.
Кнопка старого цвета удаляет соответствующее RGBA-переопределение. Рецепт сбрасывает
ручные цвета, но не изменяет позицию и хоткеи. Пипетка редактора активируется явно,
принимает клик только на холсте или в предпросмотре самого окна и читает один пиксель;
клик за пределами предпросмотра не захватывает цвет рабочего стола. В браузерном демо
цвет CSS-градиента нельзя прочитать точно — пипетка работает только с видимым текстом
и сплошной подложкой, иначе сообщает об ограничении. Пока в Win32 RGB выбирается
системным диалогом, а поле альфы доступно в инспекторе показателя; ввод HEX и альфа
для общих цветов/строк в редакторе ещё не реализованы (ключи INI уже читаются).

## [overlay_order] и [overlay_positions]

`rows` — список ключей датчиков через запятую в порядке строк. Управляется перетаскиванием
карточек выбранных строк в редакторе. Неполный, повторный или неизвестный ключ
отбрасывает весь список и возвращает порядок по умолчанию.

Кнопка «Редактор» открывает мастерскую с витриной рецептов, списком слоёв с глазиками,
холстом и инспектором строки. Навигация справа переходит к фактическим контролам,
а не к фиксированным смещениям прокрутки. Число над ползунком открывает ввод (Enter —
применить, Escape — отменить); колесо над ползунком меняет значение на 1, с Shift —
на 10. Редактор использует DPI окна для отрисовки, попадания мышью и полей ввода;
координаты строки и привязка монитора в INI остаются в прежних физических пикселях.
При открытии мастерской большой холст занимает центральную часть окна; список
слоёв остаётся слева, инспектор и небольшой предпросмотр — снизу. Кнопка «Настройки»
возвращает витрину и панели оформления, не меняя положения оверлея. Для каждого ключа секция
`[overlay_positions]` сохраняет три числа: `подпись_x,значение_x,y` (например,
`vram_used = 12,252,96`). Координаты используются при `pixel_layout = 1`; стрелки
смещают выбранный элемент на пиксель, Shift + стрелка — на десять. Масштаб и
автоматическое вписывание длинного оверлея в экран меняют итоговые экранные координаты.
В режиме «Строка» отдельные подписи и значения не перемещаются: перетаскивание сцены
меняет смещение всего оверлея; дельта на холсте пересчитывается к размерам виртуального
экрана, предпросмотр — обратно. Ctrl + клик в свободном режиме выделяет несколько
строк, которые переносятся как целые блоки. При перетаскивании Shift включает сетку
8 px; без Shift плашка притягивается к краям/центру/безопасной зоне 5 %, а строки —
к колонкам и базовым линиям других строк. Направляющие видны только в редакторе.
Нажатие «Вернуть шаблон» отключает пиксельную раскладку. Простое открытие
редактора не меняет раскладку; новые координаты начинают применяться при перемещении
элемента на холсте или редактировании чисел. Размер видимого оверлея можно менять
перетаскиванием нижнего правого угла; при наведении на экранную плашку видны
ручка масштаба снизу справа и ручка отступов внутри сверху слева (кроме RTSS-слоёв
и пиксельной раскладки, где отступы задаются иначе). Ctrl + колесо меняет масштаб
на 5 %, Shift + колесо меняет отступы на 2 px, Ctrl + Shift + колесо — интервал строк на 2 px.
Сквозной клик (F9) оставляет ввод игре и отключает эти жесты до повторного нажатия.
В режиме `pixel_layout = 1` и в готовых стилях обычные строки Yawa можно
перетаскивать прямо на видимом оверлее; стиль и расстояние между колонками
сохраняются. В готовом стиле Shift + перетаскивание строки на другую меняет
их порядок, Alt перемещает всю плашку. Смещения готового стиля хранятся отдельно
в `[overlay_style_offsets]` как `metric = x,y` в пределах −2048…2048 px при масштабе 100 %;
они не меняют `pixel_layout` и не применяются к импортированным слоям RTSS.
На холсте мастерской перетаскивание обычной строки готового стиля использует
то же смещение; явный ввод X/Y в полях пиксельной раскладки по-прежнему включает
`pixel_layout = 1`. На холсте мастерской ручка в нижнем правом углу плашки
меняет её ширину и высоту отдельно от общего масштаба; внутренняя ручка меняет
отступы (только для обычных стилей без пиксельной раскладки).
В мастерской импортированные слои RTSS показаны отдельно от показателей Yawa:
глазик скрывает слой, видимый слой можно выбрать на холсте и перетащить или сдвинуть
стрелками (Shift — шаг 10 px). Ctrl + клик на слоях или холсте выделяет несколько
слоёв для общего перемещения и выравнивания по шести границам/осям. Для выравнивания
нужно минимум два видимых слоя; опора — первый выделенный. Инспектор активного слоя
показывает редактируемые X/Y (−2048…2048 px) и ширину/высоту (0 или 16…2048 px),
кнопки сдвига и сброса вместо полей обычного показателя. Изменение ширины и высоты
затрагивает только активный слой. При отключённом сквозном клике RTSS-слой можно
перетащить и на видимом экранном оверлее;
Alt + перетаскивание двигает всю плашку.
Изменение положения хранится в `[rtss_layer_edits]` INI; текст выбранного слоя,
цвет текста `#RRGGBBAA` и размер шрифта 10–400 % можно менять в инспекторе
мастерской. Эти правки хранятся отдельно в `[rtss_layer_text]` (UTF-8 в HEX),
`[rtss_layer_color]` (RTSS AARRGGBB) и `[rtss_layer_size]`. Угол выделенного
слоя меняет его ширину и высоту; `[rtss_layer_extent]` хранит их в пикселях макета
до ZoomRatio (`0` — из исходного RTSS, иначе 16–2048). Кнопка «Сбросить правки»
возвращает исходные текст, цвет, размеры и положение, не трогая глазик.
Исходный `.ovl`/`.ovx` остаётся побайтно прежним для экспорта. Приближённые графики RTSS
`Frametime`, `Framerate 1% Low`, `CPU usage` и `GPU1 usage` (режимы 10/80/81)
рисуются только из доступной локальной истории и при однозначном HAL-источнике
для CPU/GPU; внешним провайдерам история не выдумывается. PNG-атлас из `.ovx`
или из соседнего файла при выборе `.ovl` отрисовывается только для тега
`<I=0,0,0,0,w,h>` с прямоугольником в пределах изображения. Безопасное имя PNG
не содержит путей и `..`; файл до 4 МиБ, декодированная сторона до 2048 px.
При недоступном ресурсе показывается «нет данных», а не придуманная картинка.
В прототипе для `.ovl` нужно выбрать макет и PNG одновременно (ограничение
браузерного доступа к соседним файлам); EXE читает PNG рядом с выбранным файлом.
Остальные теги изображения и режимы графиков пока не воспроизводятся. Окно мастерской вписывается в рабочую
область текущего монитора, при необходимости уменьшая масштаб интерфейса вместо
размещения контролов за краем экрана.

Текстовый RTSS `.ovl` OverlayEditor v2 (до 1 МиБ) импортируется как отдельный
неизменяемый оригинал в `[rtss_original]`: `template_hex` содержит исходные байты,
`omitted_layers` — число слоёв без однозначно связанного показателя Yawa;
часть таких слоёв теперь предварительно рисуется как текст и фон. Оригинал хранится
в общем INI или в INI игрового профиля и сохраняется при редактировании; undo/redo
не дублирует его байты в памяти. Экспорт предлагает исходный `.ovl` побайтно либо
новый шаблон из показателей Yawa. `[SourceN]` с не-HAL `Provider`, отсутствующим
или неоднозначным источником не сопоставляется с датчиком Yawa; `<FR>` встроен в RTSS.
Отдельные файлы изображений остаются внешними ссылками, Yawa их не копирует.
Импорт RTSS не является визуальной копией макета: предварительно рисуются фон,
обычный текст, координаты, размер и цвет слоя и два приближённых графика из
локальной истории, но большинство графиков, гипертекстовые условия,
таблицы и сложные теги картинок пока не поддержаны. Управляющие теги не превращаются
в повторяющийся текст «нет данных»: в предпросмотре они скрыты, исходник сохранён.
Недоступные значения явно помечены «нет данных»;
если в обычном видимом режиме отрисовка не дала ни одного пикселя, импорт отменяется
и прежний оверлей восстанавливается вместо невидимой замены. После успешного импорта оверлей
показывается сразу, если не скрыт сценой меню. Пробная отрисовка требует подтверждения. Бинарный пакет обмена `.ovx` (Layouts → Import в RTSS)
читается отдельно от `.ovl`:
поддержан контейнер `0CDU`/`0WZL` с одним текстовым `.ovl`, до 8 МиБ сжатых и
24 МиБ распакованных данных, не больше 64 вложенных файлов. Пакет проверяется
по размерам, структуре и кодам сжатия, но **не** по неизвестному внешнему полю
контрольной суммы. Ресурсы не пишутся на диск и не отрисовываются в Yawa; сам
пакет сохраняется в `exchange_hex` и отдаётся обратно без изменений, включая
картинки. `resources` хранит число файлов, кроме макета. Новый `.ovx` из оформления
Yawa не создаётся: для этого используется экспорт нового `.ovl`. Простая смена
расширения между `.ovx` и `.ovl` не работает.

## [labels]

Подписи полей в оверлее. Значение — до 10 символов UTF-8 (кириллица допустима), пустое
значение скрывает подпись целиком.

| Ключ | По умолчанию |
|---|---|
| `fps` | `FPS` |
| `cpu` | `CPU` |
| `gpu` | `GPU` |
| `ram` | `RAM` |
| `vram` | `VRAM` |

Подписи попадают в оверлей, в шапку окна мониторинга и в заголовок CSV-сессии.

## [hotkeys]

Значение — виртуальный код клавиши Windows (`VK_*`) числом: `0` выключает привязку.
Клавиши назначаются прямо в интерфейсе: нажать на строку, затем нужную клавишу.

| Ключ | Код | По умолчанию |
|---|---|---|
| `overlay` | 0x79 | `F10` — показать или скрыть оверлей |
| `position` | 0x7A | `F11` — следующее положение оверлея |
| `window` | 0x7B | `F12` — показать или скрыть окно |
| `click_through` | 0x78 | `F9` — включить или выключить сквозной клик по оверлею |

Старые ключи `toggle_overlay`, `cycle_position`, `open_window` не читаются: они дублировали
функции и мешали переназначению.

## [ui]

| Ключ | Значения | По умолчанию |
|---|---|---|
| `accent` | `mint`, `ice`, `violet`, `amber`, `coral` | `mint` |
| `density` | `normal`, `compact` | `normal` |
| `animate` | `0`/`1` | `1` |
| `close_to_tray` | `0`/`1` | `0` |

`close_to_tray` по умолчанию выключено: крестик закрывает приложение, и окно не пропадает
неожиданно. Если нужен фоновый опрос после закрытия, сворачивание включается в настройках.

## [profiles]

Профили игр пишутся отдельными секциями `[profile:<имя процесса>]` с теми же ключами,
что в `[overlay]` и `[capture]`. Профиль применяется, когда процесс с таким именем
становится активным, и откатывается при выходе из игры.
